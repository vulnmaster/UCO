# ICAC Ontology Family

A comprehensive experimental semantic framework for Internet Crimes Against Children (ICAC) investigations, supporting law enforcement agencies, digital forensics experts, policymakers, technology companies, and hotline operators in building semantically interoperable applications for child protection.

## Overview

The ICAC Ontology Family provides standardized semantic representations for complex child protection investigations, enabling effective data sharing, analysis, and coordination across multiple domains and jurisdictions. The framework covers the complete investigation lifecycle from initial NCMEC tips through final sentencing, with specialized modules for production cases, custodial relationships, victim impact assessment, ICAC task force operations, and comprehensive international coordination based on ICMEC's global partnerships with 120+ countries.

## Ontology Modules

### Core Ontologies

1. **icac-core.ttl** - Core investigation framework
   - Investigation lifecycles and case management
   - Subject roles (suspects, victims, witnesses)
   - Evidence types and relationships
   - Investigation workflows

2. **hotlines-core.ttl** - Hotline operations and report management
   - Report intake and classification systems
   - Hotline operator workflows
   - Report routing and escalation
   - Inter-hotline cooperation

3. **icac-us-ncmec.ttl** - Enhanced NCMEC integration and tip analysis
   - NCMEC CyberTipline integration with sophisticated analysis
   - Possession and transfer detection algorithms
   - Account linking and phone number tracing
   - Platform cooperation and investigation triggers
   - Tip prioritization and validation workflows

### International Coordination & Global Frameworks

## Usage Examples

### Enhanced NCMEC Tip Analysis
```turtle
@prefix icacus: <https://ontology.unifiedcyberontology.org/icac/us/ncmec/0.2#> .

ex:TipAnalysis001 rdf:type icacus:CyberTipAnalysis ;
    icacus:analysisConfidence "high" ;
    icacus:analysisOf ex:NCMECTip12345 ;
    icacus:linkedToAccount ex:SuspectAccount ;
    icacus:triggeredBy ex:PossessionIndicator .

ex:TaskForceReferral001 rdf:type icacus:TaskForceReferral ;
    icacus:urgencyLevel "immediate" ;

    icacus:resultedInInvestigation ex:Investigation001 .
```

### Production Case Analytics
```sparql
PREFIX icac: <https://ontology.unifiedcyberontology.org/icac#>
PREFIX icac-multi: <https://ontology.unifiedcyberontology.org/icac/multi-jurisdiction#>
PREFIX icac-sentencing: <https://ontology.unifiedcyberontology.org/icac/sentencing#>

SELECT ?investigation ?agencyCount ?sentenceLength WHERE {
    ?investigation rdf:type icac:Investigation ;
        icac-multi:agencyCount ?agencyCount .
    ?sentence icac-sentencing:sentenceLength ?sentenceLength .
} ORDER BY DESC(?sentenceLength)
```

### Operational Effectiveness Metrics
```sparql
PREFIX icac-tactical: <https://ontology.unifiedcyberontology.org/icac/tactical#>
PREFIX icac-undercover: <https://ontology.unifiedcyberontology.org/icac/undercover#>

SELECT 
    (AVG(CASE WHEN ?tacticalOutcome = "successful" THEN 1.0 ELSE 0.0 END) AS ?tacticalSuccessRate)
    (AVG(CASE WHEN ?undercoverOutcome = "successful" THEN 1.0 ELSE 0.0 END) AS ?undercoverSuccessRate)
WHERE {
    ?tacticalOp icac-tactical:operationOutcome ?tacticalOutcome .
    ?undercoverOp icac-undercover:operationOutcome ?undercoverOutcome .
}
```

## Installation & Setup

### Prerequisites
- RDF/OWL processing capabilities
- SPARQL query engine
- UCO/CASE ontology stack (recommended)

### Docker Environment
```bash
cd ontology/icac
docker-compose up -d
```

This provides:
- Apache Jena Fuseki SPARQL endpoint
- GraphDB instance with ICAC ontologies loaded
- Validation services for SHACL constraints

### Manual Installation
1. Import core UCO ontologies
2. Load ICAC ontology modules in dependency order
3. Configure SPARQL endpoint with inference support
4. Load example data and test queries
